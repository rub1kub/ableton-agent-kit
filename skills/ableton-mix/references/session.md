# Recording preparation and musical structure

Inspect the actual Live version/edition and existing arrangement. Do not carry tempo, lyrics, performer distribution or structure over from another song. Preserve the existing set before starting a new one. Inspect device availability, not just a product edition name.

## Beat and guide

- Use the existing beat if its source and placement are correct. Compare duration, sample hash, warp, pitch and start position. Turn Warp off only when original speed is intended and this will not break an already approved edit.
- At constant BPM, quarter-note duration is `60/BPM`; a 4/4 bar is `240/BPM`. Arrangement time is in beats. Position `bar.beat.sixteenth` maps to `(bar-1)*4+(beat-1)+(sixteenth-1)/4` only in 4/4.
- Check attack alignment near beginning, middle and end. Syncopation is not evidence that tempo is wrong. Inspect musical phrases before rearranging; extend by whole useful phrases, not by stretching a finished track to a target duration.
- Keep the original beat on an inactive archive track or as an untouched collected source. Confirm it cannot double the working beat.
- Mark sections and performer responsibilities. Empty MIDI guide clips without an instrument/output can be useful; verify their silence. One lyric line does not necessarily equal one bar: follow the user's explicit phrasing.
- Preserve the audible tail beyond the formal end marker. An outro needs actual accompaniment under the last vocal line, not an early fade just because the source file ended there.

## Tracks and routing

Use names before recording: lead, hook, optional independent doubles, adlibs and archive. Group performers or vocal roles; send each track to one intended destination. Separate dry signal and fully wet returns. Inspect track routing choices from Live rather than guessing routing strings. Confirm return sends cannot form accidental feedback.

Begin with centered lead, quieter optional doubles, conservative sends and enough master headroom. Exact faders depend on the recorded material and beat. No loudness equality can be promised for unrecorded performers. Keep each performer equally important when requested; avoid assigning one a permanent background role.

Use available native Utility, EQ, compressor, optional disabled saturation and optional pitch correction. No aggressive EQ, gate or de-esser threshold without a voice. Voice inputs and monitoring are outside project preparation unless specifically authorized.

## Takes and count-in

Prepare one-bar count-in if available; the toolbar's global launch quantization `1 Bar` is **not proof of count-in**. Read the count-in setting from a supported interface or inspect its menu. A lack of a setter is a specific limitation, not a reason to claim success.

Use take lanes when supported. Preserve every original attempt and the full source recording. For a single long take, keep it intact on an inactive archive, then edit working clips. Never manufacture separately recorded doubles by copying and labeling them as real doubles.

Start with a representative hook or short verse to set delivery and effects. If the user records everything on one track, accept that workflow and separate sections after recording. A denser track is not automatically a better recording template.
